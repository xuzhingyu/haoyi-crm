# 行业信源配置

2026-11-06 已上线到正式工作台。总部管理员在 **设置 → AI 与信源 → 行业信源** 中新增、编辑和测试信源；其他总部账号可查看来源状态，不显示配置入口，服务端同样检查 `hq_admin` 权限。

## 日常操作

1. 点击“新增信源”，填写名称、公开地址、情报分类、采集类型和采集间隔。支持 RSS/Atom 与公开网页列表；间隔为 **30–1440 分钟**，默认 360 分钟。
2. RSS 填订阅地址；网页列表可填写列表项、链接、标题和日期的 CSS 选择器。选择器格式在服务端校验。
3. 点击“测试采集”查看实际可识别数量和最多 5 条样例，包括原文链接、来源日期及已有摘要。测试不保存信源，不把测试样例作为正式情报入库，也不调用模型。
4. 点击“验证并保存”。保存时会重新检查地址与实际采集结果，不以此前测试成功代替本次验证。保存后由 AIHOT 按配置持续采集；“立即采集”会向启用来源提交真实抓取任务，并同步已有库存。新结果最迟进入下一次 10 分钟同步，也可采集完成后再次点击同步。

编辑已有来源时从该行“编辑”进入。来源 ID 保持稳定，已有情报、收藏和批注不会因为配置修改而移动或删除。暂停只停止后续采集，保留历史内容；重新启用后恢复调度。

## 验证和冲突

- 只接受不含凭据的公开 HTTP(S) 地址，拒绝本机、内网、非标准端口及携带密钥类查询参数的地址。验证时逐跳核验并固定公网 DNS 地址，读取上限 2 MB；AIHOT 在预览和正式采集时另行执行其受限抓取检查。
- 必须识别出至少一条可采集内容及有效公开原文链接才能保存。需要登录、验证码、仅依赖浏览器脚本加载或限制访问的网页，可能无法直接采集；不能仅凭网页在浏览器中打开就认定接通。
- 来源性质由服务端依据已核验域名识别。用户填写“官方”名称或上游 `T1` 标签，不会自动变成官方来源；未知域名仍标待核对。
- 编辑携带上游 `version`。配置在编辑期间发生变化时返回 409，重新打开后再修改，不能覆盖较新的配置。
- CRM 与 AIHOT 均检查重复来源。已配置地址提示编辑现有来源；上游存在而本地尚未同步时，先刷新情报与来源再编辑，不创建重复采集任务。
- 配置接口按管理员限流。429 表示操作较频繁；502/503 表示采集服务或连接未完成；错误不会作为“采集成功”展示。

## 服务边界与接口

浏览器只访问 CRM，AIHOT 管理口令和 CSRF 会话留在后端。配置保存写入审计记录；不向浏览器返回上游凭据。采集测试和内容同步不调用模型，后续研究仍走共享预算网关。

| 接口（统一 `/api/v1` 前缀） | 用途 |
| --- | --- |
| `POST /intelligence/source-config/validate` | 测试当前草稿，返回真实采集样例 |
| `POST /intelligence/source-config` | 验证并新增来源 |
| `GET /intelligence/source-config/{source_id}` | 读取可编辑配置及当前版本 |
| `PUT /intelligence/source-config/{source_id}` | 验证并保存已有来源 |

配置服务实现为 `services/lead-core/src/lead_core/intelligence/source_config.py`，路由为 `services/lead-core/src/lead_core/api/routes/source_config.py`；正式弹窗为 `apps/franchise-portal/src/pages/SourceConfigEditor.tsx`。独立 UI 规范预览仍只使用本地 fixture，不接生产配置接口。

完整同步覆盖 **AIHOT 已采集的上游库存**：首次分页快照、后续水位增量及每日完整复核。它不等同于某网站的全部历史，也不把 RSS 摘要称作全文。RSS 只提供其当前窗口内的条目；已授权旧 RSS 的一次性回填和部署顺序见 [旧工作台信源接续](legacy-news-sources.md)，发布与运行约束见 [工作台部署](workspace-deployment.md)。
