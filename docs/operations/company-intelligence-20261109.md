截至2026-11-09，本次完成本地实现、真实授权查询和首次资料整理。未执行生产部署，不能据此声称线上每日采集已经运行。

## 已采集范围

- 用户指定的容大、浩宜、横保3家主体，以及天眼投资树中浩宜持股超过50%的14家投资企业，共17家。包括已注销的潍坊公司，保留其历史资料；另外两家少数股权投资不当作子公司。间接多数持股递归查询已执行，未返回更多下属主体。
- 天眼记录484条，另有公开资料24条；数量是索引和观察记录数，不是独立经营事件数或风险事件数。相同事件可能有不同来源，页面保留来源证据。
- 天眼维度：工商登记、对外投资树、风险总览、新闻舆情、招投标、工商变更、资质。列表逐页请求，每页20条；响应结构、页数上限、授权、额度或分页异常均标记部分完成，已取得的资料保留。
- 风险总览的自身、周边、历史和预警分别保留，不相加，也不把诉讼/提示认定为违法。招投标保留本企业角色和公告中标方，避免把关联公告当作本企业中标。
- 微信公众号可被天眼新闻索引命中，但部分记录不返回原文链接，此时只链接企业资料页并明确“原文待核验”。未接入公众号全历史订阅，不能保证全网全量、删除文章或未公开资料覆盖。
- 司法案卷明细、知识产权全部明细、年报全部字段等不在当前自动采集维度，不能将总览当作完整档案。子公司按公开多数持股识别，协议控制及少数持股实控需进一步核验。

## 页面与运行

工作台新增 `/haoyi/companies`（开发站为 `/companies`）。总部账号读取；只有 `hq_admin` 可以启动历史回填或立即更新，CEO保持只读。支持企业、类别、发现日期和分页筛选。来源、核验状态、原始日期与发现日期分开显示。

服务端接口 `GET /api/v1/company-intelligence`；`POST /api/v1/company-intelligence/collect` 接受 `mode: baseline | daily`。每日北京时间08:45由现有Celery Beat执行。日报按首次入库的北京时间日期计数，历史回填不会冒充当天发布。任务单实例、5分钟重复请求抑制、队列失败显式报错；不发送邮件或微信消息。

天眼调用消耗天眼账号额度，与现有研究模型每日20元预算分别管理；本模块不调用大模型。日常查询仍分页检查新闻/招投标并去重保存，递归检查多数持股企业；历史回填另取工商变更和资质。授权过期或额度不足时停止后续天眼调用，保留当前资料并显示部分完成。

本机 `tyc-cli 0.3.11` 已经OAuth授权并真实查询成功。凭据由官方CLI保存在当前用户私有目录，未写入项目文件。技能已加载：[天眼一下](https://www.tianyancha.com/ai/skills/skill.md)，依据[官方接入指南](https://www.tianyancha.com/ai/guide.md)。

## 生产启用步骤（尚未执行）

1. 备份数据库，使用现有部署流程发布前端构建与后端。新增数据库表由0006迁移及工作台现有迁移入口支持，先迁移再启动API。普通前端构建不包含独立UI样板。
2. 对 `infra/deploy/compose.workspace.yaml` 叠加同目录 `compose.company-intelligence.yaml`。该可选镜像安装固定版本CLI和Node；服务器需要能访问天眼服务。原运行环境的OIDC、业务数据库和其他服务配置沿用原文件。容器镜像构建/服务器资源和长期调度尚未验证。
3. 以运行服务的用户完成一次服务器授权。使用同一Compose组合执行 `run --rm --no-deps worker node /opt/tyc-cli/dist/index.js login --no-open --no-block`，按实际返回的URL和验证码在浏览器授权，然后同一组合执行 `run --rm --no-deps worker node /opt/tyc-cli/dist/index.js login --resume`。登录状态保存在命名卷 `tianyan_credentials`；不要复制个人配置到源码、镜像或日志。
4. 启动API、worker、scheduler。只有worker挂载凭据卷，API与scheduler不持有天眼凭据。仅运行一个Beat；确认数据库迁移、队列和实际任务成功后才能宣布每日任务已启用。
5. 在“企业动态”启动一次更新，检查任务状态、来源错误和新记录；次日08:45检查定时任务与日报。上游未收录与来源失败都不能解释为无风险。

非容器环境配置：`LEAD_CORE_COMPANY_INTELLIGENCE_TIANYAN_ENABLED=true`、`LEAD_CORE_COMPANY_INTELLIGENCE_TYC_CLI_ENTRY=<tyc-cli/dist/index.js绝对路径>`，Node可通过 `LEAD_CORE_COMPANY_INTELLIGENCE_TYC_NODE` 配置。默认不开启后台天眼查询；CLI入口固定为服务端配置，不接受浏览器传入命令或可执行路径。进程执行不用shell。

## 数据与验证

- `data/company-intelligence-seed.json` 与 `data/company-intelligence-tianyan-seed.json` 为可审阅采集资料；对应包内 `baseline.json`、`tianyan-baseline.json` 随后端发布。种子初始化幂等，不在GET接口中写入。
- 采集原始返回只保存在忽略提交的 `.runtime/company-intelligence/`；应用种子去掉企业联络电话、邮箱等无关字段，仅保留任务所需企业公开信息。
- 自动测试覆盖HQ/CEO/加盟商权限、北京时间日界、分页/去重、标签修正、失败/额度停止、递归股权、shell参数与凭据错误脱敏。前端覆盖筛选、只读账号、队列及轮询。
- 本地UI测试使用独立预览fixture，不证明生产身份、真实服务调度或移动实体设备验收。真实天眼首次采集与本地数据库导入另行验证。
