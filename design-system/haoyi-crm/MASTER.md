适用于浩宜统一工作台的全业务、桌面和移动端。视觉方向：**灰蓝环境、实白内容、蓝青品牌色与柔软新拟态**。用户于 2026-11-09 确认组件展厅风格并授权迁移到正式业务页面；v1.2 统一正式材质与动效，保留权限、字段、操作流程与统计口径。本轮为本地实现与预览，不表示已发布。便携设计摘要见根目录 [design.md](../../design.md)。

## 1. 设计原则

> Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.
>
> 避免不必要的次要标签和描述，让布局本身来传达信息。

- 用对齐、间距、分组和操作位置表达层级，页面只保留有助于完成任务的信息。字段标签、错误、权限限制、危险后果和统计口径属于必要信息。
- 层次来自灰蓝环境、柔软投影、清晰边界和数字排版。导航采用浅灰蓝，内容、表格、图表与浮层使用不透明表面；不用背景模糊、大面积霓虹、循环扫光或科技文案堆叠。
- 一屏一个主任务，一处操作区一个主按钮。界面层级为导航 → 页面 → 区块 → 控件，避免卡片里再无意义地套多层卡片。
- 日常操作优先，长列表和密集业务数据保持稳定位置；动画不抢占阅读和输入。状态同时用文字表达，不单靠颜色。
- 以当前服务端权限、状态和时间为事实源。原 CRM、公开线索和研究数据不能未经口径核验直接相加。

## 2. 色彩与语义 Token

新组件使用语义变量，不在业务组件中重复写裸色值。正式页面的材质与动效定义集中在 `src/ui/tokens.css`、`src/ui/motion.css`；独立样板仍使用隔离的 `src/ui-spec/`。下表固定设计值，不与商业指标分类色混用。

| 语义 | 值 | 用法 |
| --- | --- | --- |
| 页面背景 | `#EAF0F4` | 工作区底色 |
| 内容表面 | `#FFFFFF` | 表格、正文、图表和主要内容卡片 |
| 品牌主色 | `#2462E8` | 主按钮、主要链接、焦点、主数据系列 |
| 主色 hover | `#1D54CE` | 主按钮悬停／按下反馈 |
| 选中背景 | `#E5EDFB` | 当前导航、选中行、浅色强调 |
| 科技辅助色 | `#0B7480` | 次级数据、少量重点边线和图标 |
| 辅助色背景 | `#EDF7F6` | 轻量辅助强调 |
| 主标题／重要值 | `#20364A` | 标题、金额、关键对象名称 |
| 正文 | `#334B60` | 业务内容 |
| 次级文字 | `#4E6577` | 字段元数据、说明 |
| 弱化文字 | `#4E6577` | 非关键辅助信息，仍须检查对应底色对比 |
| 分割线／边框 | `#DCE5ED` | 内容分隔；不能单独承担控件可识别性或焦点提示 |
| 成功／成功底 | `#15803D` / `#F0FDF4` | 成功、已完成 |
| 警告／警告底 | `#B45309` / `#FFFBEB` | 即将到期、需注意 |
| 错误／错误底 | `#DC2626` / `#FEF2F2` | 错误、危险、逾期／禁止联系 |

危险按钮保留 `#DC2626` 配白字；浅红底标签使用独立文字变量 `--hy-danger-text: #B91C1C`，避免直接用 `#DC2626` 配 `#FEF2F2` 时对比度只有 4.41:1。该状态文字对比度约 5.91:1。

表单控件边界、聚焦环和重要图形不得仅依赖很浅的分割线色；采用足够对比的边界或清晰填充，并按实际相邻颜色检查。状态浅底配对应深色文字，禁止在浅色背景上使用低对比亮青文字。

分类图表依次选品牌蓝、青、紫、深橙、深灰蓝，配合图例、线型和数据表；颜色代码由图表主题集中定义。错误／成功语义色不作为默认普通分类色。

### 材质与层级

| 层级 | 材质 | 用途 |
| --- | --- | --- |

| 内容层 | 不透明白 `#FFFFFF`，边界 `#DCE5ED` | 表格、正文、图表和主要内容卡片 |

## 3. 字体、数字与密度

正文优先使用本机系统字体，不强制加载远程字体：`system-ui, "Segoe UI", "PingFang SC", "Microsoft YaHei UI", "Noto Sans SC", sans-serif`。中文按可用中文字体回退；数字用 `font-variant-numeric: tabular-nums`，编号、请求 ID 等用 `ui-monospace, Consolas, monospace`。

| 层级 | 字号／行高 | 字重 |
| --- | --- | --- |
| 页面标题 | 24 / 32 px | 600 |
| 区块标题 | 18 / 26 px | 600 |
| 卡片标题 | 16 / 24 px | 500 或 600 |
| 桌面正文／表格 | 14 / 22 px | 400 |
| 移动正文／输入 | 16 / 24 px | 400 |
| 辅助文字 | 12 / 18 px | 400 |

字重仅使用 400、500、600。辅助字号不承担主要业务内容。数值右对齐、名称左对齐、状态保持一致位置；币种和单位清楚但不重复。不要全大写英文字母、宽字距汉字或所有标题加粗。

默认标准密度：表格行高不低于 48 px；桌面允许用户切换紧凑密度 40 px。移动端不使用紧凑行，触摸操作区域不低于 44×44 px；多行长名称允许自然增加行高。

## 4. 空间、容器与响应式

- 间距只用 `4 / 8 / 12 / 16 / 24 / 32 / 48 px`。控件内常用 8–12，相关控件 8，区块内 16–24，区块间 24–32。
- 圆角：复选框等选择标记 5、按钮／输入／选择器控件 12、面板／卡片 20、主要浮层 20 px。单选标记保持圆形；状态小标签可采用紧凑形状，避免所有元素胶囊化。
- 分隔以 1 px 边框和留白为主。面板使用克制的二级阴影，浮层使用三级阴影；正文与表格不叠加透明材质或多重阴影。
- 正式侧栏采用工作台直接入口与四个可展开／收起的业务分组；同时只展开一组，子项缩进表达第二级。首页默认分组全收起；路由变化自动展开所属组，手动折叠不被普通数据刷新打断。身份无权访问的项目先过滤，空分组不显示。
- 桌面侧栏 224 px，顶栏 56 px，内容外边距 24 px。`768–1279 px` 使用 200 px 的完整文字侧栏，取代旧 64 px 图标栏，让二级目的地保持可辨识；内容按可用宽度减少列数。`<768 px` 使用最大 280 px 的抽屉导航，关闭后焦点返回触发按钮。
- 移动内容外边距 16 px；表单单列，工具条按优先级换行，主操作保持可见。布局不出现整页横向滚动。
- 新增、编辑、确认与一般信息查看默认使用居中对话框。确认框 440 px，通用表单／详情 720 px，AI 助手使用 880 px 居中工作弹窗；宽度不超过视口减 32 px，最大高度为 `calc(100dvh - 32px)`，内容内部滚动。手机普通弹窗仍居中并保留 16 px 边距。
- 侧边抽屉仅用于需要对照列表或连续处理记录的业务详情，例如客户、批次、商机、加盟详情；常规 560 px，复杂详情 720 px，只有此类真正的抽屉在窄屏转全屏。不可因为复用同一组件就将所有弹窗统一成侧边抽屉。
- 需要横向比较的表格允许自身滚动，提示其可滚动；不得为适配手机缩小字体。固定表头、底部动作区要避让焦点、软键盘和安全区域。

## 5. 图标、动效与可访问性

使用现有 Lucide SVG 图标体系，常规 16／20 px，导航 20 px，线宽保持一致。图标与文字间距 8 px；没有语义价值不加图标。图标按钮必须有可访问名称，Tooltip 不代替名称。不可用 emoji 作为正式操作图标。

图标按钮新调用显式使用 `iconOnly`，采用与同尺寸按钮一致的方形点击区域；不依赖“是否缺少 children”的兼容推断。Checkbox、Radio 和 Switch 保留原生 input 语义，定制可见外观；单选组共享 name，多选框支持 mixed 状态，Switch 表达即时开关，不冒充表单单选。Select 在视口 `<768 px` 时使用原生 select，其余宽度使用桌面自绘弹出列表；键盘、标签、错误和选中值关联必须一致。粗指针仅扩大触摸目标，不单独切换 Select 渲染分支。

正式页面采用以下动效矩阵。优先改变 `opacity`、`transform`，不动画化 blur，不使用循环数字跳动、扫光和自动旋转。现有 3D 地图仅属于特定区域视图，不扩散到列表、图表或普通布局；保留平面／列表替代和降低动态方案。

| 场景 | 进入／反馈 | 退出／限制 |
| --- | --- | --- |
| 页面、卡片 | 360 ms 淡入与小幅上移 | 错峰间隔 40 ms，最大延迟 200 ms；刷新、排序不重播整页 |
| 可交互卡片 | 180 ms，视觉层抬升 4 px | 命中区域、焦点环和布局占位固定；纯数据卡不抬升 |
| 控件／导航 | 180 ms／240 ms | 提交中保留尺寸；不移动命中区域 |
| 对话框 | 320 ms，96% 缩放并上移归位 | 180 ms；退出完成才释放模态约束 |
| 抽屉、移动导航 | 360 ms 滑入 | 200 ms |
| Toast | 220 ms | 160 ms；消息时限遵循原有反馈规则 |
| 真实条形与进度图形 | 480 ms，一次性展开 | 最终尺寸取真实数据，不递增伪造数值 |

按钮压缩回弹使用独立内部材质层，文字、焦点环与命中区域稳定；禁用、忙碌、失焦及页面隐藏时取消反馈。卡片入场与悬停使用独立视觉层。仅首页少量重点卡在精细指针悬停时允许最多 4 px 的装饰光泽响应，内容不倾斜；离开、页面隐藏或偏好改变时复位。`prefers-reduced-motion` 与 `forced-colors` 下关闭位移、缩放、错峰及指针光泽，立即呈现完整内容；偏好在动画中改变也必须立即完成到正确状态。

### 降级与对比度

- 正式材质默认不透明，不依赖 `backdrop-filter`；内容、操作与布局在不支持视觉特效的环境保持完整。
- 用户要求降低透明度时使用不透明背景并关闭 blur／环境光干扰。正式页面与样板均支持 `prefers-reduced-transparency` 和 `html[data-hy-transparency="reduced"]` 明确选择；各入口保持样式隔离。`prefers-reduced-motion` 下移除非必要过渡和环境运动，静态层级不影响操作。
- `forced-colors` 模式去掉柔光、半透明、阴影和模糊，使用系统颜色与可见实线边框；原生选择语义、选中标记和焦点仍可辨认。
- 在最终合成背景上检查文字、焦点和控件边界对比度，不能只用纯白底的计算结果证明全部状态已通过。长正文和数据区保持不透明以减少背景变化。

可访问性目标为 WCAG 2.2 AA：普通文字至少 4.5:1，大字至少 3:1，必要控件边界／图形与焦点可见性按相应标准检查。项目触摸目标采用 **44×44 px**，比 AA 的目标尺寸最低要求更保守，二者不混称。支持键盘、可见焦点、弹窗焦点约束与返回、语义标签和错误关联。

参考：[文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[目标尺寸最低要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。这些是验收依据，不构成未执行检查的通过声明。

## 6. 落地与维护

### 历史实现：液态玻璃与空间层次（2026-11-06，材质已由 v1.2 替代）

本轮将玻璃材质和丰富动效落到正式工作台及旧 CRM 模块。环境、内容、导航／操作、浮层形成四个层次；加强蓝青边缘高光与投影，正文、表格、输入及图表仍使用实白阅读底。正式首页将真实五指标与待办组合为重点区，下方保留情报、研究、额度的双栏；经营概览保留地图中轴、两侧业务区和底部图表。其他页面保留主要操作位置，不增加装饰性说明文案。

正式浮层以统一 presence 生命周期保留退出中的内容与模态控制。关闭先经过原有 dirty／busy 判断；保存业务与反馈即时执行，退出仅控制显示生命周期。退出完成后再卸载、解除滚动锁及返回焦点；快速重开取消旧退出任务，嵌套从顶层依次关闭。正式代码不导入样板入口和 fixture，独立样板不连接生产 API／OIDC。本节说明实现目标与约束，验证状态及未完成项以 acceptance.md 为准，不表示已发布上线。

正式构建的本地视觉预览在 `apps/franchise-portal` 运行 `npm.cmd run build` 后执行 `npm.cmd run preview:visual`，地址为 `http://127.0.0.1:4176/`。预览脚本 `scripts/preview-visual.cjs` 通过 `scripts/visual-fixtures.cjs` 提供测试响应，绑定回环地址，使用 `connect-src 'self'` 限制连接；脚本不读取 `.env`，测试数据不打入正式构建。该入口用于本地审阅，不代表真实业务接口或线上身份验收，也不替代独立样板入口。

### 本地预览的卡片与动效细化（2026-11-06）

按本次明确的页面优化与丰富动效要求，独立样板采用有主次的 Bento 分区：经营摘要、优先待办、图表分别组织，避免等权指标卡墙。重点金额允许使用 `--hy-font-featured: 48px`，手机收敛到 32px；其余字阶、实白内容底、16px 面板圆角与蓝青语义色保持一致。具体布局见 pages.md。

该次独立样板采用一次性卡片入场 320ms、真实条长展开 480ms，提供小幅错峰、列表更新和按钮反馈；数值只揭示最终真实文本，不递增虚构中间值。样板浮层为 220ms，环境柔光静止，无循环装饰。键盘聚焦不重播入场；`prefers-reduced-motion` 与 `forced-colors` 关闭这些效果并立即呈现内容。此处保留样板实现记录；正式页面以第 5 节的新动效矩阵为准。

规范基于现有 React／Vite 技术栈与用户确认的展厅。shadcn/ui 的清晰组件层次、Uiverse 的柔软材质、SaaSFrame 的表单排版仅作为视觉参考；不复制业务功能，不新增正式依赖。Hallmark 用于设计复核与根 design.md 整理，技能建议不是服务端规则来源。

规范优先级：当前任务的明确要求 → 根 `AGENTS.md` → 本 MASTER → 对应组件／页面／图表细则。局部差异必须说明用途，不能通过多个 CSS 覆盖文件积累暗中例外。组件契约以实际导出的类型为准，变更契约时同步规范和样板。

独立样板入口为 `apps/franchise-portal/ui-spec.html`，实现隔离在 `src/ui-spec/`，仅用本地 fixture，不请求业务 API。使用 `npm.cmd run dev:ui-spec` 预览 `http://127.0.0.1:5174/ui-spec.html`；使用 `npm.cmd run build:ui-spec` 输出 `dist-ui-spec`。普通业务构建不包含样板，生产部署不自动引入它。

本轮迁移在共享 token、theme-light 与 motion 层实施，覆盖正式工作台、情报、研究、拓展、协作、经营及设置；不删除原业务 CSS，也不改变权限、数据口径或业务规则。所有检查和已知未完成项记录在 [acceptance.md](acceptance.md)。
