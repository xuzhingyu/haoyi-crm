# 浩宜 CRM 图表规范

本规范以 [MASTER.md](MASTER.md) 为视觉基线。组件样板中的图表使用明确标注的本地示例数据；下表记录的是当前代码可提供的数据能力，不表示样板已经接入业务 API。

## 1. 选择图表

| 要回答的问题 | 默认图表 | 使用条件 |
| --- | --- | --- |
| 当前多少、较目标还差多少 | 数值卡、进度条 | 显示单位、统计期间与范围；无比较期不显示涨跌 |
| 各地区、各阶段、各来源谁多谁少 | 水平条形图 | 从零起轴，长标签左对齐；排名按值排序，业务阶段按流程排序 |
| 随时间如何变化 | 折线图 | 有真实、连续定义的时间桶；断档显示缺口，不能补零或自动插值 |
| 同一类别下几组如何比较 | 分组柱图 | 默认最多 3 组，最多 12 个类别；更多类别用筛选或表格 |
| 总量由哪些部分组成 | 堆叠条形图 | 各段互斥且可相加；预算的已用、预留、剩余分别表达 |
| 一个明确任务完成了多少 | 单项进度条 | 分子、分母与单位一致；分母为 0 时显示“暂无记录” |
| 地理分布在哪里 | 平面地图＋排名列表 | 地理位置是决策因素时使用；缺失地区列为“未分配”，地图保留表格替代 |
| 同一批客户逐步转化多少 | 真正的转化漏斗 | 只有同批对象、进入阶段事件和统一窗口均可获得时启用 |

环图限于一个比例或不超过 5 类的组成，比例与原始数并列。阶段存量默认条形图。不得为了科技感增加 3D 柱图、立体饼图、旋转地图、装饰雷达或没有业务单位的仪表盘。

## 2. 当前数据能力

API 路径均相对于前端配置的 API 根路径，`/crm` 代表原业务服务桥接前缀。

| 数据来源 | 当前可用字段／能力 | 合适的呈现 | 限制 |
| --- | --- | --- | --- |
| `/crm/dashboard/personal`、`/crm/dashboard/executive` | 线索、商机、加盟、培训记录数，预计管道金额，月订单容量 | KPI、经营摘要 | 支持本月／上月／本季度；不能自行把金额标为实际收入 |
| Dashboard `funnel` | 每阶段 `count`、`estimated_value` | 阶段数量条形图 | 当前阶段存量，不是历史转化漏斗 |
| Dashboard `regions` | 省市、线索、加盟、月订单容量，批次、商机、交付风险等 | 区域排名、分组条形图、平面地图 | 不同指标时间口径可能不同，具体按接口定义标明 |
| Dashboard `training` | `total`、`completed`、`completion_rate` | 完成进度、记录数 | 按培训记录统计，不擅自改写为人数、门店数或有效交付率 |
| Dashboard `risks`、`unknowns` | 逾期跟进、缺少下一步、应用状态未知 | 风险列表、计数 | 未知不等于正常；没有评分模型时不造“健康分” |
| `/workspace/overview` | 可领取线索、有效领取、逾期跟进、商机、待办、文章；公开线索商机阶段数量 | KPI、阶段存量图 | 公开线索和原 CRM 是不同数据域，不直接相加为唯一客户数 |
| `budget` | `daily_limit`、`spent`、`reserved`、`remaining`、`currency` | 三段预算进度条 | 当日 CNY；预留不等于已经花费；以服务端结果为准 |
| `/crm/studio/summary` | 主体、合同、纪要、已完成报名数量 | KPI | 不是完整财务汇总或统一客户去重结果 |
| `/crm/studio/contracts/{id}/totals` | 加盟／培训净收款、培训应收、名额，派单／完工／结算／到账金额，兑现和逾期 | 单合同金额明细、名额与履约进度 | 限有权操作员；兑现依据由合同约定决定，不能统一当到账口径 |
| 统一待办的数据适配结果 | 旧业务待办去重后与新工作任务组合 | 待办数量、状态列表 | 任一必要来源失败时不能显示貌似完整的总数 |

依据为当前 `services/legacy-crm/app/analytics.py`、`services/legacy-crm/app/studio.py`、`services/lead-core/src/lead_core/api/routes/workspace.py` 和预算网关代码；接入时仍须核对实际响应与授权。

## 3. 预留能力与接口缺口

| 拟用图表 | 现有缺口 | 接入前必须完成 |
| --- | --- | --- |
| 线索与签约趋势折线图 | Dashboard 未提供按日／周／月时间序列 | 增加聚合接口，明确时区、起止范围、时间桶和每条序列的事件日期 |
| 同比／环比、迷你趋势线 | 缺少统一比较期、基期与完整性标志 | 同口径比较；基期为零、未知或缺失时返回不可计算状态 |
| 真实转化漏斗／阶段转化率 | 现有数据是阶段存量 | 定义同批线索、观察窗口、进入阶段事件、回退与流失规则，再做服务端聚合 |
| 收款、退款、净收款趋势 | 已有明细和单合同汇总，缺少授权范围内的全局按期聚合 | 以收付款发生日聚合；净收款扣除退款；明确取消／更正处理，避免前端对当前页求总量 |
| 团队人效、跟进时效分布、任务热力图 | 缺少全量完成事件与统一分母 | 明确人员归属、事件日期、工作日／自然日、可见范围及迟到数据处理 |

当前代码的部分区域比较使用“本期签约数 ÷ 本期新增线索数”；两者并不保证是同一批客户。新规范使用“区域线索与签约规模”对比，不将该比值称为转化率。业务接入前须独立修正旧实现；样板不能冒充此修正已经完成。

## 4. 统一绘制规则

- 图表标题回答业务问题，标题下只保留需要判断的期间／单位；复杂口径放入可访问的“口径”说明。不要重复标题、副标题、卡片标签三遍。
- 默认高度 260–320 px，移动端 220–260 px；紧凑进度条不套用此高度。图例在图上方，窄屏自然换行，不覆盖绘图区。
- 主系列用品牌蓝，比较系列按 MASTER 的分类色顺序；同一指标跨页同色。红／绿主要保留给风险／成功语义，变化方向不直接等同好坏。
- 柱图从零起轴；折线若裁切纵轴必须清楚显示尺度。避免双 Y 轴；不同单位使用并列小图。不要用 8% 的最小柱宽夸大很小的值。
- 默认展示至多 5 个系列。小于 0 的有效值保留负号；金额用千分位，金额单位固定于标题或轴；百分比一般 1 位小数。
- 同屏避免元、万元混用；若按万元缩放，Tooltip 和替代表格同时提供精确元值。预计管道价值、合同金额、应收、净收款、到账分别命名。
- 0 是真实零值；`null`、未知、未采集显示“—”；错误显示“加载失败”；分母为零不显示 0% 作为伪结论。
- Tooltip 支持键盘焦点或触摸点击，包含类别、时间、系列、原始值与单位；不依赖 hover 才能理解关键结论。
- `ChartFrame` 提供图表可访问名称、状态提示与数据表替代。数据表与图使用同一输入；视觉隐藏图形时仍能访问数据。
- 异步加载保留框架和尺寸；刷新失败保留最近成功数据并显示“更新失败”，初次失败显示重试。所有来源未齐时标注“不完整”，不得静默求总和。
- 空态显示“暂无记录”并按上下文提供操作。图表不会为了填满版面生成随机数据或虚构趋势。

## 5. 样板与真实接入

组件样板仅从本地 fixture 读取可重复的数据；页面清楚标注“示例数据”。样板演示成功、空数据、加载、错误及受限等状态，不访问 OIDC、数据库或业务 API。样板中的按钮交互只改变本地演示状态。

真实接入须另行完成权限核验、聚合接口与数据口径验收。引入图表库之前先确认实际交互需求；样板所用 SVG／CSS 不构成后续全站图表库选型的强制依赖。
