# 浩宜 CRM 页面与产品设计规则 v1.2

本规范覆盖当前 `/haoyi/` 统一工作台的全业务和桌面／移动端。视觉基线见 [MASTER.md](MASTER.md)，组件交互见 [components.md](components.md)，指标口径见 [charts.md](charts.md)。独立样板展示可复用结构；正式页面最新实现与验收范围见 acceptance.md 的 v1.2 迁移记录。

## 1. 信息架构与页面模板

沿用当前“工作空间、客户拓展、业务协作、经营管理”分组，正式侧栏改为可展开／收起的二级导航。工作台保留顶层直接入口，其余模块为分组子项，同时只展开一组；不叠加第三层菜单。侧栏只列当前身份可进入的主要模块，权限过滤后不显示空组；页面内继续用标签页切换相关视图。列表返回后恢复查询条件、排序、页码／游标和滚动位置。

### 二级导航交互（2026-11-09）

- 首页默认所有业务组收起；直接进入详情、跨组跳转或浏览器前进／后退时展开目标所在组。用户仍可手动收起当前组，其父按钮保留当前分组提示；数据刷新不重置折叠选择。
- 组标题使用原生按钮与 `aria-expanded`／`aria-controls`；Enter、Space 切换，Tab 只访问可见子项。收起内容使用 `hidden`，不能只降低透明度。叶子保持真实路由链接和 `aria-current="page"`，支持新标签页打开。
- 研究详情对应 AI 研究，账号页面对应设置；领取后跟进与拓展商机对应客户拓展的已领取线索工作区，页面内的公开线索工作区 Tabs 保留。菜单改造不调整路径、接口、权限或业务流程。
- CEO 继续仅显示工作空间和经营管理，经营概览指向 `/crm/executive`；加盟商只显示工作台与客户拓展中原有授权入口。总部业务入口不因折叠而扩大权限。
- `≥1280px` 侧栏宽 224px；`768–1279px` 为 200px 文字侧栏，保持二级目的地可读；手机沿用最大 280px 的模态抽屉，点叶子后关闭，保留背景锁定、Escape、退出动画和焦点恢复。
- 组按钮至少 48px，子项至少 44px；展开仅 180ms 淡入与小幅位移、箭头 240ms 旋转。减少动态或强制颜色时立即呈现最终状态，并保留系统色边界与焦点。

| 页面类型 | 桌面布局 | 移动布局 | 主要操作 |
| --- | --- | --- | --- |
| 工作台／经营概览 | 页面标题与期间筛选 → 左经营摘要、右优先处理 → 区域与阶段图表 | 重要待办优先，经营摘要次之；次级指标两列，图表单列 | 处理当前待办、查看业务记录 |
| 列表页 | 标题＋一个主操作 → 常用筛选 → 结果表 → 分页 | 标题与主操作 → 搜索／筛选入口 → 字段卡片；比较型数据允许局部横滚表格 | 新增／领取／导入中与当前任务最相关的一项 |
| 详情页 | 对象标题、生命周期状态、主操作 → 主要字段 → 业务标签页／时间线 | 单列；固定底部动作区仅用于必要操作，留出安全区 | 跟进、变更状态或确认 |
| 新增／轻量编辑／一般查看 | 默认居中对话框；一般表单／详情 720 px，确认 440 px | 保持居中、两侧至少 16 px，正文内部滚动 | 保存、取消、确认 |
| 连续业务详情 | 需要对照列表或连续处理时使用侧边抽屉 | 此类抽屉可转全屏 | 查看相邻记录、处理当前记录 |
| 长表单／完整业务流程 | 独立页面，相关字段分组，底部保存区 | 单列字段，清晰的步骤与保存反馈 | 提交当前步骤 |
| 研究／报告 | 标题与状态 → 进度 → 正文／引用 → 可执行建议 | 正文优先，引用与建议按区块展开 | 停止／重试／确认建议依状态出现 |

不把每个模块都做成统计卡墙。不在列表上方固定放置没有决策价值的四张指标卡。金额、日期和状态统一对齐，让布局表达信息层级。

### 正式工作台与经营概览（2026-11-06）

总部工作台上部将现有五个业务指标与统一待办组成主次区。“客户线索”在指标组内突出，跟进记录、商机、加盟档案、培训记录保持原始口径与跳转；CEO 五指标仍为不可点击的数据展示。待办移到相邻重点入口，数量仍由现有统一去重逻辑提供，加载失败不显示伪造的零。下方保留左情报、右研究及 AI 额度的双栏结构，不新增说明性小标题。

加盟商工作台继续显示组织可访问的四项指标与商机阶段汇总，仅统一材质、间距和交互反馈，不引入总部情报、研究和业务入口。所有计数、金额、链接、加载异常和权限判断沿用现有业务数据；不新增装饰趋势或虚构统计。

正式经营概览保留地图中轴、两侧业务区及底部图表，通过重点指标、风险区域、留白和一次性错峰强化层次。客户列表、详情、表单、研究和设置保留主要操作位置。桌面卡片在充分空间内组合，窄屏自然折为单列／双列；不压缩字段字号来维持桌面构图。具体动效和降级见 MASTER 第 5 节。

经营地图为原有默认 `network` 模式补充可见的“全部”单选项，使默认状态有对应选择标记；不增加新的地图数据模式或改变统计口径。正式正文采用桌面 14／22 px、手机 16／24 px，单选标记、标签和操作目标在强制颜色及窄屏模式下仍须可辨识。

### 独立样板的概览与列表

经营概览使用 Bento 组合布局。桌面左侧经营摘要以“预计管道金额”为重点，下面并列“本期新增客户”“在跟进商机”“本期签约加盟”三个次级指标，并保留缺少下一步的客户入口；右侧“优先处理”呈现待办数量、逾期提示及具体任务。窄屏改为先待办、后摘要，DOM 顺序也以待办优先，手机图表单列。金额的 48 px 重点字阶及手机 32 px 回退见 components.md 的局部差异说明。

“区域客户分布”和“阶段分布”放在摘要与待办下方，保留单位、期间、口径和替代表格。缺少历史时间序列的趋势占位从默认概览移除；这不代表已具备趋势数据，接入条件仍以 charts.md 为准，不得填充装饰性假曲线。

客户列表把搜索、筛选、数据与分页放在同一个实白容器内。桌面关键列采用明确宽度，表头、地区、金额和日期不因窗口变窄逐字换行；长名称可以换行，空间不足时仅表格局部横向滚动。手机保留信息卡与 44 px 触摸操作，不能缩小正文来容纳桌面全部列。

### 独立样板的预览工具

侧栏与 56 px 顶栏构成连续导航层，当前侧栏项和页面标题负责定位，不再重复显示单层面包屑。顶栏保留“演示数据”标记与单一可见“预览设置”入口；桌面入口为图标加文字，手机为有明确名称的 `iconOnly` 按钮。角色选择、手机预览和降低透明度集中在设置弹窗，角色选择使用 Field 提供的 ID／ARIA 绑定。

页面专属的失败、离线、空数据等切换收进默认折叠的“状态演示”，与常规业务主操作分开；折叠不移除这些示例能力。页脚仅保留本地样板和规范版本，不使用装饰性科技口号。

### 页面材质分配

全浅色蓝青环境只在页面外围形成静态柔光。侧栏、顶栏与必要的悬浮操作区使用 86% 白玻璃／16 px 模糊；菜单、对话框、抽屉使用 92% 白玻璃／20 px 模糊。手机模糊降至 12 px，抽屉内容保持实白阅读区。

正式新增、编辑、确认和一般信息查看默认居中；客户、批次、商机、加盟等需要对照列表或连续处理的详情才保留侧边抽屉。AI 助手使用 880 px 居中宽工作弹窗。普通弹窗宽度上限为视口减 32 px，最大高度 `calc(100dvh - 32px)`，内容内部滚动；手机仍保留 16 px 边距，不统一转为全屏侧边布局。

列表表体、客户字段、合同金额、研究正文、引用和图表均为不透明白底。允许工具条与正文形成清楚的材质区别，不能把每行、每个字段或嵌套卡片都做成玻璃。环境层不承载业务信息，关闭柔光／透明／模糊后不会丢失数据或操作提示。

玻璃背景上使用选择器和图标按钮时仍须符合表单与键盘语义。桌面下拉列表保证当前弹窗内可见且不被裁切；手机使用原生选择体验，切换布局不丢失选中值、标签、校验错误或焦点。导航、浮层和内容的圆角分别遵循 MASTER 的控件／面板／浮层级别。

## 3. 产品行为规则

### 列表与详情

- 常用搜索和 2–4 个高频筛选直接展示，其余进入“筛选”；显示已应用条件并能清除。结果页不重复复述筛选项。
- 选中记录后才出现批量操作区，显示数量和作用范围；不默认跨页全选。只展示服务端已有能力，不为样板新增真实批量业务接口。
- 行内保留“查看”和一个高频操作，其余放“更多”。详情主操作依据业务阶段变化；“归档”“作废”“关闭”语义明确。
- 点击行进入详情时，行内按钮、链接、复选框不能同时触发行跳转。长名称可换行，关键信息不只藏在 Tooltip。
- 从详情返回时保留上下文；数据变更导致当前项消失时解释结果并保持合理位置。

### 编辑、危险动作和并发

- 表单保持可见字段标签。必填、格式、金额单位和错误是必要说明，不受“减少次要描述”规则删除。
- 验证先定位第一个错误；保存失败保留输入。提交中禁用重复提交并保持按钮宽度；成功反馈简短，列表按结果更新。
- 普通可逆保存直接执行；删除／作废／关闭／全局退订等高影响动作需确认对象、后果和必要原因。对话框默认焦点不落在危险确认按钮。
- 页面关闭有未保存更改时提示保存／放弃；不要对未修改表单重复确认。服务端版本冲突时显示“记录已更新”，保留用户输入并提供重新核对路径。
- 领取、导入原 CRM、建议确认等沿用服务端幂等和冲突处理。请求超时不显示“失败且未发生”，应允许核对状态后重试。

### 公开线索与联系偏好

- 当前规则为领取后 2 个工作日首联、7 天活动、30 天保护；由服务端返回截止时间，前端不重新计算政策。
- 当前软拒绝进入 90 天冷却，明确退订进入全平台禁止联系；禁止联系仅总部凭主动联系／新同意依据解除。该规范不更改现有规则。
- 禁止联系状态用明确文字和风险语义，禁用联系／领取动作。解除入口依接口权限出现，并保留依据字段。
- 组织边界、联系方式与来源证据只按授权展示；缺失显示“未提供”，无权访问不伪装为数据为空。
- 原公开线索的加盟商及时间水印、无导出规则保留。原 CRM 已有授权报告下载不因此被统一禁止。

### AI、研究与情报

- 事实、推测、建议分明；引用可定位来源。展示真实任务阶段，不能用定时器制造精确完成百分比。
- 阻塞时给出实际原因，如额度不足；失败时可重试；停止说明已发出的请求仍可能结算。研究结果不能自动修改正式业务。
- 正式业务建议确认时呈现对象、修改前后和必要依据；权限不足、记录已变更、已被处理、处理中分别表达。
- 情报同时保留来源性质、发布／采集时间。新情报与旧资讯历史不伪称已全量迁移。

## 4. 内容、格式与异常

按钮使用具体动词：新增线索、保存、领取、记录跟进、确认、重试。避免“立即开启智能体验”等营销用语。页面标题只出现一次，不加重复英文副标题或装饰编号。

时间默认北京时间，日期 `YYYY-MM-DD`，精确操作记录可显示 `YYYY-MM-DD HH:mm`；相对时间保留可访问的完整时间。金额保留货币和业务口径，编号保留完整字符串，手机号与真实隐私字段按权限脱敏。空字符串、零值、未知、无权限分别表达。

列表、表单、详情、图表均需覆盖：首次加载、刷新、空记录、筛选无结果、请求失败、无权限、成功。错误消息提供可执行下一步，禁止展示服务器堆栈或凭据。登录过期时提示重新登录，并尽可能保留未提交的本地内容，不绕过 OIDC。

## 6. 正式列表分页与布局修正（2026-11-09）

本节记录正式业务页面的本地更新规范，补充前述样板阶段的范围说明。保持 v1.2 材质、原有业务能力与操作顺序；测试、截图和实际完成的验证另记于 acceptance.md，不由本节宣称通过或上线。

### 首页与研究记录

首页客户线索、跟进记录、商机、加盟档案、培训记录在宽屏共用同一标签行与数字基线；客户线索保留深蓝强调，原有五项统计口径和入口不变。窄屏以完整指标块重新分栏，不让首项跨行造成其他指标错位，也不靠缩小字号保持五列。

研究记录放入独立实白面板，范围切换和状态选择器均按 48px 控件高度对齐，保留“状态”标签。桌面筛选组之间留出 24px；手机切换组占满一行，状态筛选另行排列，行内标题／日期／状态／关注按钮按各自空间换行，避免图标挤压正文。

### 分页范围与数据来源

| 页面／列表 | 分页来源与范围 |
| --- | --- |
| 原 CRM 客户线索、商机列表、批次、加盟档案、培训、知识、报告快照、通知 | 对接口返回的完整授权数组先筛选／排序再分页；客户地图与商机看板保留完整集合 |
| 机构、合作、沟通、合同、履约、经营报告等 Studio 台账 | 共用 Ledger，含信源与偏好共 11 类台账；沿用各自查询、筛选与权限后分页 |
| 历史资讯、收藏、历史生成记录 | 对现有历史返回集合分页；不改变已停用的刷新能力，不宣称历史数据已全量迁移 |
| 原业务跟进、加盟组织、行业信源 | 返回完整集合后客户端分页；跟进的完成确认、组织成员管理与信源操作不变 |
| 统一待办 | 内部待办读完服务端所有游标，原业务待办按已有规则去重；合并后执行来源／状态筛选与到期排序，再进行客户端分页 |
| 行业情报、AI 研究、公开线索池、已领取／领取后跟进、拓展商机、内部待办独立视图 | 采用服务端游标分页；未提供总数时只显示当前页与前后翻页，不根据本页数量虚构总条数 |
| 企业动态 | 使用服务端 `page / limit / total`；筛选与每页容量变化回第一页 |
| 最近 AI 调用 | 仅分页接口返回的最近记录窗口，明确其有限范围，不提供窗口外的虚构总量 |

客户端默认每页 10 条，服务端游标与企业动态默认 20 条；各分页提供 `10 / 20 / 50` 选择。筛选变化回第一页，已知总量的列表在删除或完成后若末页清空则回到最后有效页。分页不改变既有排序含义；领取后跟进若只能排序本批结果，必须明确“本页”，不能声称是全量到期排序。

混合待办必须在排序前完成内部待办游标读取，不能边追加批次边对已翻过的页重新排序。来源有错误时保留错误与重试入口，已获得记录的数量不得冒充所有来源完整总数。翻页、筛选和刷新发生并发时只接纳当前查询结果；失败页不复用旧页记录与新页码搭配显示。

分页只控制主体列表，不截断首页少量摘要、地图／图表、看板、详情内容或选择器选项。客户、批次、商机和加盟详情的相邻记录导航仍跨越完整筛选结果，关闭详情恢复原列表上下文。客户端页码在当前组件存续期保留，不据此宣称新增跨会话持久化能力。

手机分页保留当前页和上一页／下一页，条数选择独立成行；桌面已知总量显示数字页码和区间省略。所有布局保留至少 44px 操作目标、可见焦点与原生选择语义，具体组件行为见 components.md 的“正式分页与筛选对齐”。

## 7. 加盟商中心走查修复（2026-11-09）

加盟档案采用同一实白容器内的筛选、常用视图、台账和分页。桌面列出加盟商、地区、状态、下次回访和打开入口，窄屏按记录分组呈现；选中记录有明确边界。详情使用 560px 侧边抽屉，手机转全屏，按授权区域、交付事项、回访记录分组。相邻记录导航继续作用于完整筛选结果；关闭返回原触发点，触发记录因操作离开筛选结果时回搜索框。

授权编辑使用 720px 居中表单，手机保留 16px 边距。省份、城市采用常驻标签，省份必填；独家授权保留原生复选框，标记与文字同行，点击区至少 44px。当前账号、档案、标签页隔离保存未提交草稿；主动关闭有修改的表单需选择继续或放弃，保存失败保留输入。

新增授权、确认应用、完成回访和关闭档案均显示提交状态并拦截重复操作。错误和成功反馈只属于操作的档案，浏览器历史切换记录时清除旧反馈与关闭确认。交付状态与 30/60/90 天、月度回访节点显示中文。当前可执行的应用确认或待回访作为主操作；关闭档案位于底部独立操作区，确认明确对象、状态变化、历史保留和必填原因。权限与原业务状态流转保持不变。
